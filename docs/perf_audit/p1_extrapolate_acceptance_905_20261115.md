# P1 外推联调验收（905 人，2026-11-15）

客户端：`docs/export-20261115-000623/`（`bot_count=905`）。  
服务端 A/B：`/root/metrics_P1_905_{A,B}/`（`AOI_EXTRAPOLATE=1` + `EGRESS_ENFORCE=1` + C1）。

对照：基线@905、P0@905（无外推）、P1@200。

---

## 结论

**外推链路在 905 人下是通的**（`aoi_move_start_ms_nonzero_ratio=1`），timeout **远好于基线**，但 **略差于纯 P0**；服务端 AOI 帧率相对 P0 **几乎没再降**。  
905 人外推「观感/控制面」有收益上限；下一刀应盯 **`drifted` 仍偏高**（为何匀速仍大量补发），而不是再开开关。

| 目标 | 结果 |
|------|------|
| 客户端速度字段打通 | **过**（ratio=1，with_start_ms≈全量） |
| timeout ≤10% / 优于基线 | **过**（4.79% vs 16.8%） |
| 优于或不差于 P0 timeout | **未过**（4.79% vs P0 2.65%） |
| AOI 帧/s 较 P0 再降 | **未过**（~681 vs P0 ~717） |
| 出口低于 ceil | **未过**（仍 2.60 贴顶） |

## 通俗解读

- **好的：** 比一开头好很多——自己走路超时从十七八个点掉到约 5 个点；外推字段真的在用。  
- **没达到的预期：** 200 人时外推很猛（timeout 0、AOI 占比 27%）；满员 905 后又挤回「贴顶 + drifted 多」，外推没再比 P0 省多少出口，timeout 还略回升。  
- **原因方向：** 预算仍满；大量 `drifted` 说明呈现/预测误差仍频繁触发补发，匀速少发没在满员下站稳。

---

## 建议下一刀

1. 查满员下 `drifted` 偏高（呈现推进 vs 广播速度是否一致、到点清零、误差阈值）。  
2. 暂不把 `AOI_EXTRAPOLATE=1` 当默认，直到 905 上 timeout ≤ P0 且 AOI 帧率再降一截。  
3. P0 enforce 建议继续保留（905 上仍是主收益来源）。
